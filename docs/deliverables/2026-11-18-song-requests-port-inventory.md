# Open questions: what I could not establish from the code

Unknowns, not guesses.

1. **Not run.** Nothing in the MVP was executed. Every behaviour above is read from code; where two readings were possible I said "by reading". The ones most worth a check in the demo walk: the first three requests of an empty window locking at once (SR-189); the in-flight search sharing across requests (SR-162); the family of two uploads of one song (SR-158); what the label of a greeting with status `pending` looks like next to a payment status `pending` (SR-102).
2. **The hosted build's scheduling.** Whether the hosted deployment has any scheduled call of `reconcile` is not in the snapshot: the hosting configuration was removed (`README.md`, last paragraph). I found no caller in the code (SR-151).

4. **The old API's tests.** `T:dj.test.mjs` runs against `lib/dj-api.mjs`; I did not read that file beyond the lines I cite, so I do not know which of its rules the owner relied on at the time.
5. **`public/demo/style.css`** (looks) was not read except by name; it carries no rule I looked for.
6. **Stripe adapter tests** use a mocked network; whether the adapter works against Stripe is unknown (`STRIPE.md:20` says so).
