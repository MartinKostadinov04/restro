No path lets a POS venue create, delete or re-price a POS item or section, write outside `core.apply`, or put an item back on sale beyond the POS.

- **CODE1 (high confidence).** A member sees and can press every edit control, then gets a wrong refusal: saving an item sheet edit as a member returns `not_allowed` with the toast "Only an owner or admin can mark items sold out." The composer gates only `canCreateItem`, `canDelete`, `canMarkSoldOut` by role (`apps/web/src/composer/composer-tab.tsx:176-179`; `apps/web/src/server/item-sheet/actions.ts:92,121`; `apps/web/messages/en.json:205`, `bg.json:205`). Fix: one `canEdit` (`canEditMenu(role)`) into the composer and the sheet, read-only without it; the message "Only an owner or admin can change the menu."
- **CODE2 (high).** `setItemPaymentModeAction` can set `payment_mode` on another venue's unplaced item (same organisation): `packages/core/src/apply/payment-mode.ts:115-153` (`assertActiveItems` refuses only items placed in another venue), caller `apps/web/src/composer/payment-mode-actions.ts:48`. Fix: `itemsOfVenue` as the item sheet does.
- **CODE3 (high on code, low impact).** On a POS venue a manual sold-out mark cannot be taken off: core (`sold-out.ts:105`) refuses only marking on a POS venue, but the web sets `canMarkSoldOut` false for both (`item-sheet/actions.ts:103`, `composer-tab.tsx:176`, `composer.tsx:525`, `server/sold-out/service.ts:76`). Fix: split mark (role and no till) from unmark (role only).
- **CODE4 (medium-high).** A POS stock mark never lapses once the item's link is no longer active: `packages/core/src/apply/stock.ts:104-117` (`readSlots` builds slots only for active links) used by `lapseStockMarks` (`:308`). Fix: build lapse slots from the stored till rows whatever the link state.
