# D166: A second guest asking for the same song pays the same price and moves it up: popularity, not bidding

Martin proposed it and the lead agreed, round 2 of the grilling of the Club Biad song-request prototype. Decision log: `docs/deliverables/2026-11-22-song-requests-decision-log.md` (row 1.5). Spec: [#520](https://github.com/MartinKostadinov04/restro/issues/520), feature set 8.

## Decided

- **A guest who asks for a song already in the queue pays the same one price (D162) and his support moves that request up.** One button, no auction, no amount on any screen.
- **The order is by the number of distinct guests,** earliest ask breaking a tie — **never by money**, which is the same for everyone.
- **Only requests below the awaiting-play set reorder.** Once a request has reached the DJ's working set (D164), nothing a later guest does may push it back out.
- **"Moved up" means exactly one thing:** a shorter place number, so the request reaches the awaiting-play set sooner. **No time promise** is made or implied (D165).
- **Each supporter is his own payment row** against the one request (D162, point 5). A refusal (D167) releases every one of them; a play-mark captures every one of them, each independently (D163).
- **It either secures the place or takes no money at all.** The support is atomic: a support that cannot be recorded takes nothing, as the prototype's own idempotency key and in-transaction check already do.
- **The repeat rule is the cap** (D168): supporting a request that is already waiting is not a fresh ask and is not held back by the cooldown, but asking again for a song recently played is.

## Why

Two guests wanting the same song is the commonest thing in a club, and the prototype already has the machinery — supporting someone else's request, with its idempotency key and its atomic check. What this decision changes is only what support **does** to the order: distinct guests instead of summed money. The gesture and its plumbing are a keep.

It also rewards a group asking together, and since every supporter pays the full one price, the venue earns from exactly that.

## Not decided here

Chip-ins, where several guests split one price between them (D162: the structure stays open, none is built).
