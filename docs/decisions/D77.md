# D77: A venue's menu languages come from one core function every workflow calls

A venue's menu languages come from one core function every workflow calls: connectors report which languages the till offers and how many guest-facing texts each fills; a language counts from ~20% coverage, owner-enabled languages are never removed; one main language per venue, on the venue; the language of untagged till text stays a barsy instance setting (corrected 10-12).

One central source of a venue's menu languages (Martin 10-12: "everything collected and managed centrally, workflows pull from there, logic consistent"). A connector reports facts after each complete full read: the languages the till offers, and per language how many guest-facing texts it filled (public item and category names and descriptions; the till's own name only where no public name exists, D75). Core decides, in one function every workflow calls (sync language for untagged text, new-venue languages, settings lists with coverage, composer tabs, resolver checks, publisher): a language counts from about 20% coverage; a language the owner switched on is never removed. One main language per venue, on the venue. Corrected 10-12 (Martin, plan review): the language of barsy's untagged text stays a barsy instance setting (`integrations.config.default_locale`, default `bg_BG`, D82); only the venue's main language moves to the venue; barsy's per-venue `lang_id` is revisited once its docs are read (P-09).
