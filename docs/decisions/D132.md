# D132: Three wordings settled: a stamped new bill is never resent, a payment's return address, and refunds are read, never made

Martin 11-06, through the lead: his "yes" to the repair review's item 9, "Let the lead word them" (`docs/reviews/2026-10-29-repair-review/report.md`, "Yours to decide" and "Your answers"). Sources: repair review rows RR-O7, RR-5 and RR-20 (`docs/reviews/2026-10-29-repair-review/findings.md`). The code already does what this decision says; it changes no behaviour.

- **A stamped new-bill open is read back, never resent** (RR-O7). D112 ("it sends the identical stamped request again for about a minute") and D116's Checking row ("an order opening a new stamped POS bill is resent unchanged") predate D115 ("a round that times out is checked, never sent twice") and D122 ("a timeout is read back, never guessed"). When the answer to a new-bill open is lost, Restro reads the POS back (D115's read-back) for about a minute, as for a round, and never sends the request again. D112's and D116's resend lines are withdrawn; their other rules stand.
- **A payment's return address is cleaned as the page starts** (RR-5). D127's "A redirect's address is cleaned before any request" means: the guest page removes the provider's values from the address before it makes any request of its own, so they are never sent to Restro, never logged and never kept in history. The browser's own load of the return address carries them once; that load is served with `no-store` and stays in the same browser. A server-side redirect is not used, because it would lose the mark that tells the page a payment has returned.
- **Refunds are read, never made** (RR-20). D127's "Refunds stay none" means Restro never makes, changes or cancels a refund (`POST /v1/refunds` is refused to its key). The restricted key may read refunds, as it reads charges and disputes, so a refund made in the provider's dashboard shows on Tonight. D125 3.5 stands as D127 refined it.
