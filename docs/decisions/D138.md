# D138: Ending the night: the closing hour, the early end, and what no undo means

Martin and the Port flow lead session, 11-06 and 11-07. Sources as in D134; decision log Feature 6, rounds 4 to 7. Their MVP let a hostess end the evening, offered a five-minute undo of the whole close, and stored nothing about a night having been closed — so the close could run twice, and the undo reported success even where it had changed nothing.

## Martin's decisions

- **The night ends by itself.** The service day's close (07:00 by default, D45) ends the night's reservations: the seated become Finished, those who never came No-show (6.20). A night nobody closes would otherwise stay open for ever.
- **Ending the night early is an admin action** (6.20, 6.24). It previews what will change, warns when it runs before the club's closing hour and names **how many bills are still open**, and then closes every table code so no phone can order. What staff do afterwards in the POS is theirs.
  - It stays an admin action: a club that wants someone else to do it handles that through its own role settings, which is what the permission list is for (D141).
  - Closing every table code is part of ending the night at **every** venue, reservations or not, with the same open-bills warning.
- **There is no bulk undo** (6.21). A reservation closed by mistake is put back one at a time by an admin, and the Log keeps it; a party still at its table keeps its code open. A bulk undo breaks the moment anything has moved, which is how their MVP reports a false success.
- **The night's end answers what is still unanswered** (12.6): a Requested booking nobody got to is declined, its prepayment hold released and the guest emailed; a party still waiting becomes Not seated; a block is untouched. So "a request never cancels itself" means never **before** its night has passed.
- **Closing the night never moves money** (6.23). What happens to a prepayment afterwards is the club's own refund policy, through its own Stripe dashboard; see D136.

## The lead's calls

- **A closed night is a stored thing** (6.22): Restro's own service day already records it, so a close cannot run twice, and a booking added to a closed night warns.
- **The early end keeps a table whose card is still held** and closes every other code (12.17). It uses the ordering side's existing "keep paying" close; the plain close-all would cancel a guest's held card in the middle of a payment.
- **The night's end hooks onto the venue's closing hour, which already closes every code**, not onto the service day's close, which refuses while payments or sent orders are open (12.17). The day's close then only sweeps up what is left.
- **No fallback hour is needed** (12.20 of the check, recorded as 12.20's sibling): on any night a club is open there is a closing time, and a weekday with no hours is a closed day, which has no reservations.
- **Three moments were being called the same thing, and are now named apart** (13.9):
  - a night has **passed** when its service day has ended — that is when it becomes read-only (D135);
  - **the night's end** is the venue's closing hour, which closes the codes;
  - putting a reservation back (6.21) lives between the two;
  - a booking made after the closing hour is told it will be marked No-show.
