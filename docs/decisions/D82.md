# D82: Instance settings = the whole connection

Instance settings = the whole connection (connection, allergen characteristic, sync everything, all runs); venue settings = that venue (main language, menu source, sync mode automatic/manual with interval and full-read time in its time zone, own history, publishing rules, rollback pause). Neither edits the other's. Settings texts name the POS by `{source}`, never "barsy".

Settings ownership: an instance owns what is true for the whole till connection, a venue owns what is true for that venue; neither edits the other's (Martin 10-12). Instance: connection and status, system-wide reading settings (barsy: allergen characteristic, defined once per installation), "sync everything now" (an action), the run history of all its venues. Venue: main language (D77), menu source (till venue, menu category, price), sync mode: automatic or manual only (Martin: configurable), with, when automatic, the change-check interval and the daily full-read time in the venue's own time zone, its own sync history and "Sync this venue", publishing rules, and the publish pause after a rollback (T76). Moves: the default language, the sync schedule and the rollback pause leave the connection. Organisation › Domains (D80) stays organisation-level; a venue's Settings shows its domain read-only with a link. The worker still runs one read at a time per connection. The venue's Menu source card has a common part for every POS venue (instance and venue, sync mode and schedule, Sync this venue, history, held-sync warning) and a connector-supplied part shown only for that POS's venues (barsy: Price shown, Base vs Current; the menu category is no longer a setting, D88); a hand-made venue shows neither (Martin 10-12). Sync history (instance and venue) is collapsed: one line shows the last run, the list opens under a dropdown (Martin: no long scroll). Wording: every settings text that names barsy uses the connector's label (`{source}`) inside its system tab
