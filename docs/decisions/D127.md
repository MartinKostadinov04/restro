# D127: One renderer draws every guest menu from one option list; a Style is a preset of it

Martin 10-27, through the lead (Fable). Sources: the decision log `docs/deliverables/2026-10-27-menu-designer-decision-log.md` (rows 1.1–1.4, 1.15, 1.16, 1.21, 1.27, 2.2); the research behind it, `2026-10-27-menu-designer-research-synthesis.md`; the Platform's passport Design studio (`docs/platform-reference.md`, "Second copy").

The guest menu designer takes the paradigm of the Platform's passport Design studio: a well-designed, stable shell drawn from fixed choices, so a venue gets flexibility and nothing breaks.

- **One renderer, one option list.** Every guest menu is drawn by one renderer from one list of design settings. Every setting takes its value from a fixed list of options the renderer is built to draw well on a phone from 320 px up; the venue's three colours are the one free value, contrast-checked as today (D70, D93). No free CSS, no pixels, no per-item setting. The list is D129.
- **A Style is a preset of that list.** What a venue picks is a **Style** (the glossary's word from now on; "template" stays only in code and file names until renamed). Restro's premade Styles are **Basic**, **Editorial**, **Soft**, **Classic** and **Club**; a venue's own saved designs are Styles too (D128). A Style gives a value to every option, heading font and screen included; it never sets the venue's colours, Advanced colour roles, logo or body font, which are the brand. Everything stays editable after a Style is picked.
- **Basic is the base.** The renderer's base values give a plain, well-working menu anyone can use; every venue starts on Basic until it changes something. Editorial reproduces Editorial Market as drawn today (within the designer guide's floors) and is one preset over the base, not the base. No existing venue is moved onto Editorial.
- **Every component is editable.** The menu, its sections, the items in a section, each item's own page, and the bill, order, pay, receipt and call-a-waiter screens are components of the designer from the start; which of their parts vary, and with which options, is D129.
- **How a premade Style is made** (replaces D105's way). A Style is one file with one value per option; an agent fills it in, using Anthropic's design skills (D106) to pick and review the choices, and Martin checks it on a local preview before it goes live. When a Style needs a look the renderer cannot draw yet, that look is first added as a new option for every Style, with a test proving that no existing venue's menu changes ("a new option never changes an existing look"). The `template-design` and `template-review` skills are rewritten for this; Club (T87's dark club look) is the first Style made this way. Editorial Market's code becomes the renderer; `qr-phone` retires (its contract tests move to the renderer's fixtures).
- **What stays from D69 and D105.** Every Style passes the face contract on every fixture before it is offered; Martin accepts each Style himself; the functionality file (`docs/guides/menu-template-functionality.md`) remains the one list of what a guest can do, drawn by the renderer.
