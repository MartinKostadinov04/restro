# D84: Guest address = <our domain>/m/<organisation>/<venue>

Guest address = `<our domain>/m/<organisation>/<venue>`: organisation slug unique platform-wide, venue name unique in its organisation, both generated from names and editable, old names redirect; the random code is internal only; custom domains (D80) drop the path parts they cover. Supersedes D68's visible code.

Clean guest addresses, no visible codes (Martin 10-12: "I want clean names"; supersedes the visible-code part of D68). A venue without its own domain: `<our domain>/m/<organisation>/<venue>` (path form, chosen as the simplest to apply now: no wildcard DNS or certificate; `/m/` keeps guest links apart from admin routes). The organisation part is the organisation's slug, unique platform-wide; the venue part is unique within the organisation (P-08). Both are generated from the names at creation (also for venues from a POS) and editable later; an old name keeps redirecting, so printed links never break. With D80: a venue domain shows no path, an organisation domain shows `/<venue>`. The permanent random code stays only as the internal key of the published files; old `/m/<slug>-<code>` links redirect. Table QR links (`/t/<token>`) are unchanged
