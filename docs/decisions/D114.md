# D114: Agents' deliverables are filed in docs/deliverables and kept for revisiting

Martin 10-18, during the grilling of "What is a bill in Restro?" (#35): every deliverable of a worktree, session or subagent is kept in the repo, built like the decisions, but as work that can be revisited.

- **One file per deliverable:** research, an opinion, a process map or a review is one file `docs/deliverables/<date>-<slug>.md`. It names who made it (session or subagent, model) and for which ticket.
- **An index:** `docs/deliverables.md` has one row per file, with who made it, what it was for, and its status: current, revised by a newer file, or folded into a decision.
- **Informs, never binds:** a deliverable informs; only a decision (`docs/decisions/D<n>.md`) binds. Files are kept and never rewritten after filing. A newer deliverable revises an older one, and both rows say so.
- **Filing:** the lead files each deliverable, as a direct commit to the stage branch (`docs/agents/lead.md`).
- **Every grilling keeps a decision log** (Martin 10-18): one row per decision, with why, status and where it is recorded. It is kept from the first answer and reviewed by Martin before he confirms. The D-numbers and tickets are written from it (`restro-flow/build.md`).
- **Replaces wayfinder's convention:** a deliverable is never only a chat message, a notes folder or an unmerged branch. This replaces wayfinder's `research/<name>` branches that are never merged. The files on those branches were copied in on 10-18. `docs/research/` keeps its older material.
