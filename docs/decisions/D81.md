Settings › Integrations is source-agnostic now: chosen systems (saved) each get a tab of named instances (connection, status, system settings, sync, history; "Add {system}"); New venue picks an active instance and its venue, or "By hand". Organisation Settings › Integrations is source-agnostic, built in this phase (Martin 10-12: "not tailored to barsy"; brings forward the screen and named-connection parts of the plan D79 parked; the Mistral connector and the engine work stay parked). An owner chooses the systems they use from the ones we support; the choice is saved for the organisation, and each chosen system gets its own tab. A tab holds that system's named instances ("barsy – Sofia"), each with its connection form, status, system-specific settings (barsy: allergen characteristic), sync schedule, sync now and run history; "Add {system}" adds another instance. New venue asks for the source: an instance with an active connection (then a venue of that instance; one already linked shows "linked to …" and can't be picked) or "By hand", which skips all of it; the backend is the same. The Till venues card goes. Removing an instance is refused while any venue is linked to it (move or delete those venues first); unselecting a system is refused while it has instances. Connections are never erased (disabled instead). Needs a name per connection and a stored list of chosen systems (migration)
