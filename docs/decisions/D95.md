# D95: Areas and tables: barsy's halls and tables

Areas and tables: barsy's halls and tables (rename, reorder, hide; non-public hidden; keyed by hall id); other POS open; Restro venues make their own. Menu routing for all venues: venue (live menu) → area → table, one menu per level, most specific wins, unpublished falls back. Tables shown as a grid per area; name field labelled with the barsy number beside it. Refines D88.

Tables & QR: areas, tables and menu routing (Martin 10-12). Areas and tables by venue kind: barsy venues: halls (barsy "salons") and tables come from barsy (`Places_getlist`); rename, reorder and hide only (Restro's name over barsy's, the till untouched); non-public and placeholder places hidden by default; halls keyed by barsy's hall id, not by name. Other POS systems: open until their documentation is read. Restro (hand-made) venues: the owner creates, renames and deletes their own areas and tables. Menu routing, a dictionary for all venues: one menu per level: venue-wide (the live menu, the default), area-wide (overrides the venue), table (overrides the area); the most specific entry wins; a level without an entry inherits; an unpublished menu falls back to the next level up (D91). One code always opens exactly one menu, with no guest switch (refines D88's "several menus at once"). UI: the name field is labelled as the name guests see, with "from barsy: <number>" beside it; each area is a section with its tables as a grid of cards (name, number, code status, the menu shown, marked when overridden), actions open from the card
