# D103: Keep the D43 hosting split through 10 clubs; agent time goes into portability, not moves

Martin prefers spending agent time on being ready to migrate over paying for bigger plans before product-market fit (10-17). Hosting stays as D43 and D54 set it: Postgres on Supabase (Ireland; free plan, Pro before money flows; database host only, its Data API, Auth and Storage off) and the web app and worker on Railway (EU West, Hobby plus usage). Expected cost, excluding the AI subscription and the venues' payment fees: about 10 to 15 a month at the pilot before money flows, about 35 to 40 once Supabase Pro is on, about 55 to 80 at 10 clubs, about 200 to 300 at 50 clubs; ceilings 100 at 10 clubs and 500 at 50. A move or a bigger plan happens only on a trigger: a reliability incident on a service night, or the bill crossing about 100 a month. Neon, Railway Postgres or a VPS are acceptable alternatives for any part when a trigger fires.

(Corrected 10-17, same day: the first text of this decision assumed Postgres on Railway, from a stale copy of the stack doc; D43 stands.)

Portability is prepared now, so the move is a redeploy: a container image for web and worker; object storage behind one S3-compatible module; pg-boss as the only queue; standard Postgres with no host-specific service; separate Postgres schemas for the core, auth, jobs, guest events, money and bookings, with no foreign keys from events or money into the core except by id, so guest events and payments can move to their own instance or an edge ingest without touching the menu engine; a tested restore from the R2 dumps.

**Per workload** (the lead's technical call, accepted by Martin 10-17): pg-boss stays the only queue; auth sessions stay in Postgres under Better Auth; no cache service, because the CDN is the guests' cache and the admin needs none; guest events go through one ingest module with batched inserts that never joins core tables, so it can move to an edge ingest (a Cloudflare Worker and queue) without touching anything else.

**Backups:** hourly dumps to R2 during service hours, nightly otherwise; one restore drill before the first club goes live. Point-in-time recovery (about 100 a month) is decided at go-live with paying clubs, not for the pilot.

The portability work is task T85.

Guest events are a first-class, append-only, personal-data-free event model in their own schema from the start, because Martin wants quality analytics and the questions it must answer are written now (T84).
