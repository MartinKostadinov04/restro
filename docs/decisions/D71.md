# D71: Guest features are venue settings in the composer

Guest features are venue settings in the composer; a guest sees a service only if the venue switched it on, the platform supports it, the channel is interactive and a confirmed table token is present; allergen information can never be switched off; no ordering, payment or barsy-write backend before Stage 4/5.

Guest features are venue settings, switched on and off in the composer (Martin 10-11: "bring them up in the frontend and in stage 4 we will also develop that functionality through the platform. Call a waiter and the rest of the menu functionality should be settings in the composer (appear/hide)"):
- Platform features: filters, call a waiter (with its request kinds), the bill, ordering, pay.
- Template features: for example the layout switch.
- The designer's service screens (bag, bill, call a waiter, pay, receipt) are ported into the template now.
- A guest sees a service only when all four hold: the venue switched it on; the platform supports it (Stage 4: ordering, waiter, bill; Stage 5: pay); the channel is interactive; a confirmed table token is present.
- The admin preview shows services with demo data, marked "preview".
- Allergen information can never be switched off (R6).
- Still no ordering, payment or barsy-write *backend* code before Stage 4/5
