# D100: A guest feature declares whether it needs a table code

D71 shows a guest a service only when the venue switched it on, the platform supports it, the channel is interactive and a confirmed table token is present. Song requests (D99) may be opened to guests without a table (Martin 10-17: bidding on songs does not require a table; ordering does, because the POS works with tables).

Refinement: every guest feature declares whether it needs a table code. Ordering, the bill and calling a waiter keep the requirement, because they act on a table in the POS. Song requests do not when the venue allows open access; a request made without a table is marked "online" on the DJ's screen instead of a table. The other three conditions of D71 stand for every feature. The DJ role (D99) is an organisation role with access only to the request queue of its venues.

How a guest without a table reaches an open feature (a hyperlink, a QR code shown on the club's screens, a share-as-QR button in the guest page) is grilled when the song-requests prototype is ported (T81); today every QR code leads to a table.
