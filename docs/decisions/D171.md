# D171: The venue's settings for song requests, and the defaults an owner never has to think about

Martin, round 3 of the grilling of the Club Biad song-request prototype: he asked for the list and the defaults, and the defaults are the lead's, from the club's own numbers and the research, not his to supply (`technical-tuning-from-best-practice`). Decision log: `docs/deliverables/2026-11-22-song-requests-decision-log.md` (row 1.9). Spec: [#520](https://github.com/MartinKostadinov04/restro/issues/520), feature set 9.

## Decided

| Setting | Default | Why that default |
| --- | --- | --- |
| Song requests on or off | off | A venue turns the module on deliberately (D155). |
| Price of a request | the club's own figure, in the venue's currency | One price (D162), integer minor units. |
| Free requests allowed | **off** wherever a price is set | One queued behind every paid request cannot reach the DJ on a busy night, so leaving it on would publish a place that cannot move (D162). |
| Size of the awaiting-play set | 3 | What the club runs, and the prototype's fixed window (D164). Adjustable from the DJ's own screen as well, because the person who knows the number is the DJ. |
| Automatic stop before the planned end | 30 minutes | The club's answer; the DJ also opens and closes the door himself (D168). |
| Same song again, not within | 30 minutes | The club's answer as amended (D168). |
| How long a held request may sit unplayed | 90 minutes | Martin's own figure, round 4; it is D163's release, and the only published neighbour sets a comparable limit at 45 minutes. |
| Tied greetings | off, with their own price | A venue's choice, not a default (D169). |
| Free-standing greetings | off, with their own price | Separately switchable; a venue may want tied ones only (D169). |
| Show guests' names | on, and each guest still chooses whether his own shows | D162; TouchTunes' "Anonymous" is the same idea. |

- **Who may open and close requests** is not a setting: it reuses the roles that already hold the ordering pause (D168).
- **A price change mid-night does not re-price the requests already waiting** (D162, point 4).
- **There is no blocked-artist or blocked-title-word setting, and no genre setting** (D167). The screen says why, in the venue's own words, rather than offering something that cannot be kept.
- **There is no intake cap** (D168).

## Why

Every setting here is one a club actually asked about or one the prototype already had. The list stops where the DJ's own controls begin: the door, the play-marks and the size of his set are his night, not the owner's settings screen.

## Not decided here

The settings screen itself, which takes these rows under the existing venue-settings pattern (`docs/guides/operational-screens.md`) or stops and asks for a screen plan (D123, D156).
