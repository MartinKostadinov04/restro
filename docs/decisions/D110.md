# D110: Restro writes into a POS only as a waiter would

Martin 10-18, while charting the ordering map: "Not being allowed to write in the POS is plainly stupid because this means we can just read it and show the menu, which doesn't bring additional value to the clubs." Restro works as a digital waiter: through the POS's API it does what a waiter does at the POS's front end. Martin rejected a list of calls approved one by one ("code that is wired properly in a test environment for one POS will run like that everywhere"); the limit is the kind of write, not a list of calls.

**Rule 7, new text.** Restro writes into a POS only as a waiter would. Through the API it does what a waiter does at the POS's front end: open a bill, add a round, split or move a bill, take a payment, ask for the bill or a receipt, and cancel within the POS's own rules. It never does back-office work: it never touches items, prices, settings or users (this matches rule 5 and D87). Menu sync stays read-only. Development and tests never run against a live venue's POS.

- **Why the last sentence:** Н-18 Annex 29 т. 20 forbids test runs on a live venue's system (fiscal research 10-17, G6); D33's test installation is where a connector's writes are proven.
- **Not waiter actions:** subscribing to POS webhooks and registering Restro as a POS device are setup, not service; they stay as D41 has them (polling, no webhooks) until a decision changes that. D26's translation push writes item texts, which is back-office work: it would need its own decision.
- **The guardrail changes shape, it does not go away (D67).** The test that pins `packages/barsy/src/write/` to an empty export list is replaced, in the ticket that adds the first write, by a test that every exported write is declared as one of the waiter actions above. Until then the write module stays empty.
- **Unchanged:** the CLAUDE.md scope line (no ordering, payment or webhook backend code until the tracker opens it), rule 5 (we never re-price or un-hide), rule 9 (one API user per connection per environment).
