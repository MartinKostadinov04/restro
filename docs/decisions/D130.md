# D130: Sold-out and unavailable items are hidden; scheduled items are out of scope

Martin 10-27, through the lead (Fable). Sources: the decision log `docs/deliverables/2026-10-27-menu-designer-decision-log.md` (rows 1.19, 1.23, 1.24).

- **An item that cannot be had is not shown.** When the POS stops selling an item or a manager marks it sold out for tonight (D46), the guest page does not draw it at all. "If something is not available anymore we don't show it, it's hidden – as simple as that" (Martin 10-27). This reverses D22 (sold-out items greyed out with no order button) and the glossary's *Sold out*; rule 5 allows it (hiding only makes the menu more cautious). The shell's `soldOutDisplay` default becomes `hide` and the `show` value goes; the designer gets no sold-out option.
- **Scheduled items (available from a time) are not in scope.** The platform deals with sold out only; the `scheduled` item state and its "from 18:00" label leave the functionality file's supported list. No decision ever defined them; the shell's state code made them look supported. The closed-menu note for a whole menu (`menu.schedule`) is a different thing and stays.
- **Orders and bills are unchanged:** a line that goes sold out between the menu and the POS still makes the order "Not sent" (D116), and a sold-out line cannot be ticked at Pay (D117).
- **Sold out tonight** in Structure (D46) stays as the manager's control; what changes is only what guests see.
