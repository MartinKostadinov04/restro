# D80: Custom domains (owner self-service, subdomains only, guest menu and table codes only)

Custom domains (owner self-service, subdomains only, guest menu and table codes only): each domain serves one venue or the whole organisation (`<domain>/<venue>`); verified by DNS, HTTPS automatic; routed from a published domain file, never the database (rule 4).

Custom domains for the guest menu (Martin 10-12). Per domain, the owner chooses its target: one venue (the whole domain opens that venue's menu) or the organisation (`<domain>/<venue>` for each of its venues). Subdomains only (e.g. `menu.club.bg`, one CNAME); only the guest menu and table-code pages are served on it, never the admin. Owner self-service in Settings › Domains: Restro shows the DNS record, verifies it and enables HTTPS automatically (lead's proposal: Cloudflare for SaaS custom hostnames, since Cloudflare already fronts the app; pricing to confirm). Rule 4 holds: publishing writes a domain index file (`d/<host>.json`), and the guest route resolves the host from it, never from the database. A host belongs to one tenant system-wide; an unverified domain serves nothing; removal also removes it at the provider. QR codes use the active domain (supersedes D61's forwarding workaround); our own address keeps working, with the canonical link pointing to the domain. Open: unique venue address names per organisation for organisation domains
