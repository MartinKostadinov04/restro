# D88: A venue holds several menus, exactly one live

A venue holds several menus, exactly one live (chosen in Settings › Menus or the composer). barsy venue menus = barsy's designated roots (public menu live by default, till tree). Several menus at once is per QR code/hall. Import menu: hand-made venue to hand-made venue only, one-time copy. Replaces one-menu-per-venue (P47).

A venue holds several menus; exactly one is live (Martin 10-12; replaces "one menu per venue", P47). A hand-made venue: menus are added in the venue's Settings › Menus (each row has ">" into the composer) or in the composer ("Add menu"); the live menu, the one piped to the guest page, is chosen in either place. A barsy venue: its menus are the roots barsy designates for it: its public menu (`public_cat_id`, live by default) and its till tree (`cat_id`); barsy has no menu object, other branches are only categories (back office, other brands), and sub-branches are sections (lead, from the API fields read 10-08/10-09; exact doc wording to re-check). Several menus at once is configured per QR code or hall (Martin's proposal, lead agrees; detail with Tables & QR): a code without its own choice shows the venue's live menu. Import menu (Settings and composer, "From other venue" → pick a menu): Restro-to-Restro only, between hand-made venues, as a one-time copy; menus of POS venues can't be copied (a limitation, for later). Structure: menus become many per venue, each with its own published version
