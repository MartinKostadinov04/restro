# D73: What is set once for the organisation and what per venue

(Refined by D81, D82, D87.) Organisation-wide (Settings → Integrations): the barsy connection, the barsy venues found (Add as venue / Link to an existing venue / Not used), the allergen field and text language, the sync schedule, "sync everything" and run history. Per venue: identity, Menu source (its barsy venue, menu category, which barsy price), publishing rules, composer, Design, tables, publishing. Price per venue because barsy prices by venue; reading and deletions per catalogue because venues share catalogues.

What is set once for the organisation and what per venue (Martin 10-11: "integration is a platform-wide action currently nested within an individual venue… the logic is broken"; "use [your research on barsy's structure and prices] to take the decision"). Confirms T68 and D64's shape:
- Organisation, Settings → Integrations: the barsy connection (address, API user, password, status and check, the till's currency check); the barsy venues found, each Add as venue, Link to an existing venue or Not used; how barsy data is read for the whole installation (the allergen field, the language barsy texts are written in); automatic sync (check every N minutes, the daily full read in Sofia time), "Sync everything now" and the history of all runs.
- Venue: name, menu address, time zone, service day end, languages; Menu source (its barsy venue, shown read-only with a deliberate change step; its menu category; which barsy price its menu shows; last sync, "Sync this venue", the held-sync warning); its publishing rules (publish after a sync or wait; new items shown or held, CF-04); the composer, Design, Tables & QR and Publishing.
- The price is per venue because barsy's price rules apply by article, time, venue and client, and `current_price` is the price "in the context of a specific till": two venues on one catalogue can charge differently (T71, barsy's docs read 10-11).
- Reading and the schedule are organisation-wide because items live in catalogues that venues can share: one complete read of a catalogue serves every venue on it, and deletions are concluded per catalogue (T71). Each venue's sale state and price are read in that venue's own context.
- Replaces the Integration tab inside a venue
