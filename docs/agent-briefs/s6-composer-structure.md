## Goal
The composer has two subtabs, Structure and Design, and works on the menu named in the URL (one of the venue's several). Structure: a hand-made venue creates, edits and deletes menus, sections and items; a POS venue edits a mapper (its own sections, items moved between sections, order) and a dictionary (our name, description and photo over the till's), hides, marks sold out and tags, and never creates or deletes items or till sections nor changes prices. Each section is vertical or horizontal, published as a layout hint the face renders (a horizontal section is the delivered feature strip, for any section); the menu's layout (list, one column, two columns) and whether guests may switch are menu settings, replacing the template options `layout`, `layoutSwitch` and `featureFirstSection`. "Overrides to review" is a badge on the item. The Guest features panel moves to the Design subtab.

## Do

3. **Menu layout (D92):** the snapshot carries the menu's `layout` and `layout_switch` (from `menus.settings` at publish, through `publishMenu`'s builder input; defaults `list` and `false`); the shell exposes them on the view model (`view.layout`, `view.layoutSwitch`) and the face reads them instead of its options; the manifest options `layout`, `layoutSwitch`, `featureFirstSection` go (the Design tab's option cards for them go with them). In Structure: a "Menu layout" control (default + "guests may switch") saved with `setMenuSettings` through S4's menus actions (add `setMenuSettingsAction` there if S4 did not).
4. **Hand-made venues:** rename and delete sections (delete removes the section and unplaces its items into the unplaced pane; the history keeps the record), delete items (`archive` in the change set), rename items inline; everything that exists stays.
5. **POS venues:** own sections may be created and deleted; till sections only hidden (the delete action refuses `till_section`); items moved between sections and reordered (placements); no item create or delete, no price field editable (the item sheet already refuses); the dictionary stays the item sheet (name, description, photo).
6. **"Overrides to review":** the panel goes; each item with a stale override (`loadDraft` → `staleOverrides`) gets a badge in its row and a note in its sheet. Load them with the composer's view (one read).
7. **Wording:** BG + EN through next-intl; `{source}` for the POS name.
8. **Tests:** core: the template field and the snapshot builder (a horizontal section's hint; the menu layout fields; an old snapshot without them still validates), the publish of a menu with settings; shell: the view model fields and the contract harness (the face's fixtures carry a horizontal section and both layouts; `packages/shell/testing/contract.ts` only tightens); face: the strip drawn for a marked section and not for an unmarked first one; web: component tests (the switcher, the subtabs, the layout toggle, the menu layout control, which actions a POS and a hand-made venue see, the badge), action tests (delete section / item on both kinds; `till_section`), and `apps/web/e2e/composer.spec.ts` updated to the subtabs and the URL (the keyboard reorder case is known flaky, T75: run it alone once if it fails).
